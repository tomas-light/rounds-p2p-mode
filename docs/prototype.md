# Минимальный сетевой прототип

Прототип проверяет главный риск проекта: может ли актуальная обычная ROUNDS провести матч через сервер на ПК игрока без RoundsWithFriends, UnboundLib и DuctTape. Реализованы отдельный BepInEx-плагин, управление встроенным Luxon v1.5 и подключение непосредственно к нему по UDP/IPv4. Это промежуточный этап, а не весь интерфейс из требований.

Эта страница описывает первый этап 0.1.0. Актуальный сценарий версии 0.2.0 с лобби и подключением через Steam описан [отдельно](steam.md).

## Сборка и запуск

Нужны Windows, Steam с ROUNDS публичной ветки, .NET SDK 10.0.201 и среда выполнения .NET 9 для тестов. Плагин собирается для Unity Mono (`netstandard2.1`), ядро — `netstandard2.0`, тесты — `net9.0`. Для сборки используются локальные игровые DLL; в распространяемый ZIP они не попадают. Путь игры задаётся через `ROUNDS_GAME_DIR`, параметр MSBuild `GameDir` или `local.props`.

Команда `./scripts/build.ps1` подготавливает ссылки BepInEx, получает фиксированный сервер с проверкой SHA-256, собирает код, запускает модульные и сетевые тесты и создаёт `artifacts/RoundsP2PPrototype-0.1.0.zip`. Ссылки загрузчика берутся из отдельного профиля `Rounds P2P Prototype` или уже подготовленного локального кеша. Можно передать другой профиль с BepInEx через `-LoaderProfile`. Игровые моды и патчеры оттуда не копируются.

На этом компьютере создан профиль r2modman **Rounds P2P Prototype** с BepInExPack_ROUNDS 5.4.1901. Команда `./scripts/install-profile.ps1` устанавливает ZIP только в этот профиль и отказывается смешивать его с другими модами. Для записи вне репозитория в ограниченной среде может потребоваться разрешённый запуск команды с расширенными файловыми правами.

Обычный запуск:

1. Запустите Steam, затем профиль **Rounds P2P Prototype** через r2modman.
2. Нажмите F8 в главном меню.
3. На хосте оставьте `Server IPv4` равным `127.0.0.1`, укажите доступный другу IPv4 хоста в `Host IPv4 reachable by friend`, задайте имя комнаты и нажмите `Host on this PC`.
4. Друг указывает IPv4 хоста в `Server IPv4`, такое же имя комнаты и нажимает `Join host`.
5. Следуйте штатному приглашению игры вступить с помощью пробела. Дальше работают обычные выбор карт и матч.

Для проверки двух клиентов на одном ПК оба адреса — `127.0.0.1`. Для разных ПК нужен доступ к UDP-портам 5055 и 5056 на хосте. Скрипты не добавляют правила firewall и не меняют настройки роутера. В этом этапе нет автоматического обхода NAT и приглашений через Steam.

Сервер проверяется по фиксированному хэшу, запускается скрыто с отдельной конфигурацией и останавливается владельцем сессии. Перед подключением плагин ждёт реальных UDP-слушателей, а не просто завершения `Process.Start`. Подключение ограничено таймаутом; выход и ошибка отменяют ожидающую корутину и восстанавливают изменённые настройки Photon. Изменения формата сетевых параметров применяются только во время сессии прототипа.

## Проверки и доказательства

Финальная проверка 17 ноября 2026 года: сборка без предупреждений и ошибок, **89 модульных + 8 сетевых тестов прошли**, проверки установки, повторной установки и отказа от некорректных пакетов прошли. Последний игровой прогон на этом коде — `artifacts/game-smoke/20261117-225516/result.json`: оба клиента зафиксировали `winner=0;rounds=5:0;limit=5`, подтвердили лимит комнаты 2; хост прошёл отмену и повтор подключения. Этот прогон выполнен с видимыми окнами и обычным звуком. Собранный плагин установлен в выделенный профиль; его хэш совпал с хэшем проверенной сборки.

17 ноября 2026 года свежая команда официального SteamCMD `+login anonymous +app_info_update 1 +app_info_print 1557740 +quit` показала build `21020021` для ветки `public`. Он совпал с установленной игрой. Старые ветки `old-rounds-for-mods` и `version_1.1.1` не использовались. Исходный ответ сохранён в `artifacts/verification/steam-public-build.log`.

Модульные тесты проверяют настройки и границы допустимых значений, недопустимые адреса и содержимое конфигурации, жизненный цикл процесса и проверку бинарника. Генеративные проверки перебирают значения октетов и ASCII-символов, включая попытки внедрить дополнительные строки YAML. Отдельно проверяется совместимость сетевого формата лимита комнаты.

Интеграционные тесты запускают настоящий Luxon и используют Photon UDP-библиотеки из установленной игры: создание комнаты, подключение двух участников, свойства комнаты, надёжные события в обе стороны, вложенные данные и Unity Vector2, кеш событий для позднего подключения, отказ третьему игроку и распространение отключения. Они также проверяют готовность портов и отказ при занятом порте, владение процессом: ошибка логгера и повторный Dispose не должны оставлять собственный сервер или останавливать другой сервер. Отсутствующие зависимости считаются ошибкой, а не пропуском теста.

Найден и воспроизведён дефект совместимости: текущая ROUNDS отправляет `MaxPlayers` как `int`, тогда как Luxon v1.5 ожидает `byte`. Без адаптации сервер допускал третьего участника. Узкий адаптер преобразует это поле на границе отправки; регрессионный тест требует отказа `GameFull` третьему игроку. Проверка внутри Unity дополнительно требует, чтобы оба клиента увидели лимит комнаты 2.

`./scripts/game-smoke.ps1` создаёт изолированные игровые копии, запускает сервер через наш плагин и проводит полный автоматизированный матч двумя настоящими клиентами. Только с явным флагом `--rounds-p2p-smoke` включается отладочный драйвер: он вступает в игру, выбирает карты и вызывает штатный метод `HealthHandler.CallTakeDamage` с большим уроном на клиенте владельца проигрывающего игрока. Далее работают обычные сетевые сообщения урона, смерть и начисление очков; поля счёта и лимит побед тест не меняет. Это проверка жизненного цикла матча, а не стрельбы или попаданий пуль. В этом режиме отключена запись Steam-статистики и достижений. Звук сохраняется; только явный параметр `-Mute` отключает его для конкретного запуска. Для наблюдения добавьте `-Visible`: откроются два обычных окна ROUNDS, доступных через Alt+Tab. После проверки они закроются автоматически.

Игровая проверка требует согласованного результата обоих клиентов, пяти выигранных раундов у победителя и выбора карт обеими сторонами. Хост также проходит отмену первой попытки и повторный запуск с проверкой восстановления настроек. Отпечатки игровых DLL и движка проверяются перед использованием тестовых копий, чтобы после обновления не запустить устаревшие файлы. Журналы, отпечатки и результат JSON сохраняются в `artifacts/game-smoke/<время запуска>/`; игровой прогон не входит автоматически в обычный `build.ps1`.

## Границы прототипа

Полный матч подтверждён для двух игровых процессов на одном ПК с транспортом через loopback и отдельным серверным процессом. Это не проверка игры с другом через интернет. Работа на двух физических компьютерах, прохождение NAT, реальное улучшение задержки, устойчивость к потерям и длительные серии матчей ещё требуют проверки.

Показанный в диагностике `UDP server RTT` — задержка до сервера, а не согласованный в требованиях ping между игроками. В этом этапе ещё нет Steam-приглашений в нашем сценарии, общего счёта побед и отсчёта «3, 2, 1». Штатные правила и проверки синхронизации игры сохраняются.

Luxon в текущей конфигурации не проверяет Steam-личность участника. Имя комнаты не является паролем или механизмом аутентификации. Advertised IPv4 задаёт адрес, возвращаемый клиентам, а не сетевой интерфейс прослушивания. Прототип не предназначен для открытого публичного сервера.

ZIP содержит наш плагин, его ядро, сервер и лицензию; нужен отдельный загрузчик BepInEx. Проверена установка скриптом в выделенный профиль, а не импорт неопубликованного пакета через интерфейс Thunderstore. Другу нужно передавать сам ZIP и инструкции; перенос DLL через код экспорта профиля пока не подтверждён.
